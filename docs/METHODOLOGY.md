# Methodology & Evaluation Boundaries

## Data and label

- The default example symbol is `688981.SH`; the data connector calls **Tushare's daily API**. All prices should be interpreted as raw source-provided prices unless the user preprocesses them; the repo does **not** infer corporate-action-adjusted history. Price adjustment policy matters for model validity.
- Construct 27 technical inputs using only contemporaneous or earlier OHLCV rows (returns, moving averages, RSI, MACD, Bollinger, ATR, volume ratios, etc.). Rolling warm-up rows are removed.
- At close of day `t`, feature history `[t-window+1, ..., t]` is used. The label is `int(close[t+1] > close[t])`. The final unknown target becomes `NaN` and is omitted. This is **not** an intraday classification.

## Chronology

- At each walk-forward refit, choose an inner chronological training interval and a subsequent validation interval for early stopping; the future block is untouched during this step.
- Purge one observation at the train/validation and validation/test boundaries because target `t` depends on close `t+1`.
- Fit `StandardScaler` on the inner-training interval only; reuse that fitted scaler for validation and test inputs. Fit a new scaler on each refit.
- Train with binary cross entropy and Adam; choose the checkpoint by inner-validation AUC, then score the unseen test block.
- Test blocks follow one another chronologically and may end with a shorter partial block.
- Development-only `full` mode uses purged expanding folds and fold-aware feature scaling. Results from it cannot be interpreted as out-of-sample trading performance. Optuna fits to development folds, not a truly untouched final holdout.
- The equal-weight ensemble combines four already-computed walk-forward prediction sequences only at matching dates. The results are not from weights optimized on their own test performance.

## Modeling limitations

1. **Close timing**: predicted next-bar direction is from the current bar's close to the next bar's close. The simplified backtester assumes you can transact at the just-observed close after computing the signal. This is an optimistic idealization; a truly tradable system needs a defined order cutoff, next available executable price and revised forward-return target.
2. **Cross-fold returns**: the strategy backtest is run over *the contiguous OOS prediction segment*, and all returns are within that segment. It does not count the first price move into the test segment as a strategy return. No test period is trained on its own labels, subject to the explicitly stated methodological assumptions.
3. **A-share execution**: no hard simulation of T+1 restrictions, STAR Market price limits, suspension, market impact, bid-ask spread, opening/closing auctions, lot-size restrictions, partial fills, transaction taxes or dividend mechanics. A 0.1% per-turnover commission + 0.05% per-turnover slippage are stylized defaults, not an empirical execution model.
4. **Stops**: illustrative stops use bar close, not an executable intrabar low or actual stop-order fills. No guaranteed stop execution is implied.
5. **Research degrees of freedom**: trying many models, thresholds or experimental settings and selecting by walk-forward outcomes makes those outcomes no longer strictly untouched. Future reporting should specify model selection protocol and an independently untouched last period.
6. **Comparability**: original internal archive metrics were generated by a different code path and are intentionally excluded from this repo. No historical performance numbers are asserted by the public release.

## Files written by the pipeline

For `--mode walk_forward --model lstm`, generated artifacts include `lstm_walk_forward_predictions.csv` (dated probabilities and labels), `lstm_walk_forward_folds.csv` (model refit boundaries and fold scores), `lstm_walk_forward_backtest.csv` (positions, returns, costs, equity), `lstm_walk_forward_metrics.json` and `lstm_signals.csv`. `run_metadata.json` records source type and experiment metadata. They are intentionally not in version control.

## VeighNa integration

`strategy/ai_strategy.py` is a **CSV listener, not an inference/deployment engine**. It looks up the supplied signal by an exact timestamp match and logs intended actions only. For genuine minute-level or real-time execution one must develop separate online data handling, timing alignment, model deployment, broker adapters, and compliance controls.
